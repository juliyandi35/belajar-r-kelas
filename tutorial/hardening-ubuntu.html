    Tutorial Lengkap Hardening Ubuntu

    Panduan langkah demi langkah untuk mengamankan Ubuntu, mulai dari patch dan SSH sampai audit kernel dan integritas file. Setiap langkah punya alasan, perintah, cara verifikasi, dan cara membatalkannya kalau ada yang rusak.

    Ubuntu 22.04 LTSUbuntu 24.04 LTS P1 wajib P2 sangat disarankan P3 sesuai kebutuhan

    00 Sebelum mulai: baca ini dulu

    Hardening yang salah lebih berbahaya daripada tidak di-hardening.

    Penyebab paling umum orang terkunci dari server sendiri adalah SSH, firewall, dan PAM. Jangan jalankan semua perintah di halaman ini sekaligus, dan jangan pernah langsung mencobanya di server produksi.

    Aturan keselamatan

    1. Punya akses darurat. Pastikan ada konsol KVM/VNC dari penyedia VPS, akses fisik, atau serial console. Tanpa itu, satu salah ketik di SSH bisa berarti instal ulang.
    2. Snapshot atau backup dulu. Ambil snapshot VM atau backup /etc minimal: 
      sudo tar czf /root/etc-backup-$(date +%F).tar.gz /etc
    3. Biarkan satu sesi SSH tetap terbuka saat mengubah SSH, firewall, atau PAM. Uji dari sesi kedua. Tutup sesi pertama hanya setelah sesi kedua berhasil login.
    4. Satu perubahan, satu verifikasi. Ikuti urutan bagian di halaman ini, karena urutannya disusun supaya kamu tidak mengunci diri sendiri.
    5. Uji di VM dulu, misalnya dengan Multipass (multipass launch 24.04) atau VirtualBox.

    Cek versi dan kondisi awal

    lsb_release -a            # versi Ubuntu
uname -r                  # versi kernel
who; last -n 10           # siapa yang sedang/terakhir login
sudo ss -tulpn            # port yang sedang terbuka
systemctl --failed        # service yang gagal

    Apa yang sebenarnya paling penting?

    Tidak semua langkah punya dampak yang sama. Untuk server yang terhubung ke internet, sebagian besar insiden berasal dari tiga hal: software yang tidak di-patch, SSH berbasis password, dan service yang terbuka padahal tidak perlu. Kerjakan bagian P1 dulu sampai tuntas sebelum menyentuh yang lain.

    PrioritasBagianRisiko yang ditutup

    01 Update sistem & patch otomatis P1

    Sebagian besar sistem yang dibobol menjalankan software dengan celah yang patch-nya sudah tersedia. Ini langkah dengan nilai tertinggi di seluruh tutorial ini.

    sudo apt update
sudo apt full-upgrade -y
sudo apt autoremove --purge -y
# Reboot jika kernel/libc diperbarui
[ -f /var/run/reboot-required ] && echo "Perlu reboot" && cat /var/run/reboot-required.pkgs

    Aktifkan unattended-upgrades

    sudo apt install -y unattended-upgrades apt-listchanges
sudo dpkg-reconfigure -plow unattended-upgrades   # pilih "Yes"

    Atur agar paket yang tidak terpakai ikut dibersihkan dan (opsional) reboot otomatis di jam sepi:

    /etc/apt/apt.conf.d/52unattended-upgrades-localUnattended-Upgrade::Remove-Unused-Kernel-Packages "true";
Unattended-Upgrade::Remove-Unused-Dependencies "true";
Unattended-Upgrade::Automatic-Reboot "true";
Unattended-Upgrade::Automatic-Reboot-Time "03:30";
    Kenapa file terpisah?

    File 50unattended-upgrades bawaan bisa ditimpa saat paket di-upgrade. File dengan nomor lebih besar dibaca belakangan, jadi nilainya menang, dan pengaturanmu tetap aman.

    # Verifikasi
systemctl status unattended-upgrades --no-pager
sudo unattended-upgrade --dry-run --debug 2>&1 | tail -20
cat /etc/apt/apt.conf.d/20auto-upgrades   # harus berisi "1" untuk kedua baris

    Opsional: Ubuntu Pro & Livepatch

    Ubuntu Pro gratis untuk pemakaian pribadi (hingga 5 mesin). Isinya patch keamanan untuk paket universe (ESM) dan Livepatch, yaitu patch kernel tanpa reboot.

    sudo pro attach <TOKEN_DARI_ubuntu.com/pro>
sudo pro enable livepatch
pro status

    02 User, sudo & kebijakan password P1

    Login sebagai root membuat setiap kesalahan dan setiap kompromi berdampak penuh. Gunakan user biasa dan sudo, supaya setiap aksi berhak tinggi tercatat dan disengaja.

    Buat user admin (jika masih memakai root)

    sudo adduser adminku
sudo usermod -aG sudo adminku
# Uji dari sesi baru sebelum melanjutkan:
su - adminku -c 'sudo -v && echo SUDO OK'

    Kunci akun root

    Di instalasi standar Ubuntu, root sudah terkunci. Cek dulu:

    sudo passwd -S root   # "L" = locked, "P" = punya password
sudo passwd -l root   # kunci jika statusnya "P"

    Audit akun

    # Akun selain root dengan UID 0 (seharusnya kosong)
awk -F: '$3==0 && $1!="root"{print}' /etc/passwd
# Akun dengan password kosong (seharusnya kosong)
sudo awk -F: '$2==""{print $1}' /etc/shadow
# Anggota grup sudo/admin
getent group sudo admin
# User manusia (UID >= 1000) yang bisa login
awk -F: '$3>=1000 && $7!~/(nologin|false)/{print $1, $7}' /etc/passwd

    Kunci atau hapus akun yang tidak dikenal: sudo usermod -L -e 1 namauser atau sudo deluser --remove-home namauser.

    Kebijakan kualitas password

    sudo apt install -y libpam-pwquality
    /etc/security/pwquality.confminlen = 14
minclass = 3
maxrepeat = 3
dictcheck = 1
usercheck = 1
retry = 3
enforce_for_root

    Umur password & umask default

    Edit /etc/login.defs. Perubahan ini hanya berlaku untuk user baru. Untuk user lama, gunakan chage.

    /etc/login.defs (ubah baris yang sudah ada)PASS_MAX_DAYS   365
PASS_MIN_DAYS   1
PASS_WARN_AGE   14
UMASK           027
    sudo chage -l adminku                # lihat kebijakan user
sudo chage -M 365 -m 1 -W 14 adminku  # terapkan ke user lama
    Catatan soal rotasi password

    NIST SP 800-63B tidak lagi menyarankan rotasi paksa yang sering. Password panjang ditambah SSH key dan MFA jauh lebih efektif. Batas 365 hari di atas hanyalah jaring pengaman.

    Perketat sudo

    Selalu edit lewat visudo, karena ia memvalidasi sintaks. File sudoers yang rusak bisa menghilangkan akses sudo sama sekali.

    sudo visudo -f /etc/sudoers.d/99-hardening
    /etc/sudoers.d/99-hardeningDefaults use_pty
Defaults logfile="/var/log/sudo.log"
Defaults timestamp_timeout=5
Defaults passwd_tries=3
    sudo visudo -c   # harus "parsed OK"

    03 Hardening SSH P1

    SSH yang terbuka ke internet menerima ribuan percobaan brute-force per hari. Menonaktifkan login password dan login root menutup hampir semua serangan itu.

    Urutan wajib

    1) Pasang SSH key → 2) uji login dengan key → 3) baru matikan password. Kalau urutannya terbalik, kamu terkunci.

    Langkah 1: buat dan pasang key (di komputer kamu, bukan di server)

    ssh-keygen -t ed25519 -a 100 -C "laptop-kamu"
ssh-copy-id -i ~/.ssh/id_ed25519.pub adminku@IP_SERVER
ssh -i ~/.ssh/id_ed25519 adminku@IP_SERVER   # harus masuk TANPA ditanya password akun

    Langkah 2: konfigurasi drop-in

    Jangan mengedit sshd_config langsung. Buat file di sshd_config.d/.

    Jebakan: nama file menentukan siapa yang menang

    OpenSSH memakai nilai pertama yang ditemukan untuk setiap opsi. Image cloud (AWS, GCP, DigitalOcean, dll.) sering membawa 50-cloud-init.conf berisi PasswordAuthentication yes. Kalau file kamu bernama 99-…, pengaturanmu kalah. Pakai awalan 00-.

    /etc/ssh/sshd_config.d/00-hardening.confPermitRootLogin no
PasswordAuthentication no
KbdInteractiveAuthentication no
PermitEmptyPasswords no
PubkeyAuthentication yes
AuthenticationMethods publickey

MaxAuthTries 3
MaxSessions 4
LoginGraceTime 30
ClientAliveInterval 300
ClientAliveCountMax 2

X11Forwarding no
AllowAgentForwarding no
AllowTcpForwarding no
PermitTunnel no
PermitUserEnvironment no

# Hanya user tertentu yang boleh login (ganti sesuai user kamu)
AllowUsers adminku

Banner /etc/issue.net
LogLevel VERBOSE
    Butuh port forwarding?

    Kalau kamu memakai tunnel SSH (misalnya ke database atau VS Code Remote), ubah AllowTcpForwarding ke local atau yes. VS Code Remote-SSH butuh forwarding.

    Langkah 3: validasi, lalu terapkan

    sudo sshd -t                                          # tidak ada output = sintaks OK
sudo sshd -T | grep -Ei '^(permitrootlogin|passwordauthentication|kbdinteractive|allowusers|x11forwarding)'
sudo systemctl restart ssh

    Sekarang, tanpa menutup sesi lama, buka terminal baru dan uji:

    ssh adminku@IP_SERVER                               # harus berhasil (pakai key)
ssh -o PubkeyAuthentication=no adminku@IP_SERVER    # harus DITOLAK: "Permission denied (publickey)"
ssh root@IP_SERVER                                  # harus DITOLAK

    Opsional: ganti port

    Mengganti port bukan pengamanan. Tujuannya hanya mengurangi noise di log. Kalau tetap ingin:

    # 1) Buka port baru di firewall DULU
sudo ufw allow 2222/tcp
# 2) Tambahkan "Port 2222" ke 00-hardening.conf
# 3a) Ubuntu 22.04:
sudo systemctl restart ssh
# 3b) Ubuntu 24.04 (SSH memakai socket activation):
sudo systemctl daemon-reload
sudo systemctl restart ssh.socket
# 4) Uji port baru, baru hapus aturan port 22

    Banner peringatan

    echo "Akses hanya untuk pengguna yang berwenang. Aktivitas dicatat dan dipantau." | sudo tee /etc/issue.net

    Opsional lanjutan: 2FA (TOTP) untuk SSH

    sudo apt install -y libpam-google-authenticator
google-authenticator   # jalankan sebagai user, scan QR ke aplikasi authenticator

    Tambahkan auth required pam_google_authenticator.so di /etc/pam.d/sshd, lalu di file SSH ganti ke KbdInteractiveAuthentication yes dan AuthenticationMethods publickey,keyboard-interactive. Uji dengan sesi kedua seperti sebelumnya.

    Rollback

    sudo rm /etc/ssh/sshd_config.d/00-hardening.conf && sudo systemctl restart ssh (jalankan lewat sesi yang masih terbuka atau lewat konsol).

    04 Firewall dengan UFW P1

    Default-deny untuk koneksi masuk berarti hanya service yang kamu izinkan secara eksplisit yang bisa dijangkau dari luar, termasuk service yang tidak sengaja terpasang.

    Izinkan SSH SEBELUM ufw enable.

    Kalau urutannya terbalik, koneksimu langsung putus.

    sudo apt install -y ufw
sudo ufw default deny incoming
sudo ufw default allow outgoing
sudo ufw limit OpenSSH          # izinkan SSH + rate-limit (6 koneksi/30 dtk per IP)
# Contoh service lain, buka HANYA yang kamu butuhkan:
# sudo ufw allow 80,443/tcp
# sudo ufw allow from 10.0.0.0/24 to any port 5432 proto tcp   # DB hanya dari LAN
sudo ufw logging low
sudo ufw enable
sudo ufw status verbose numbered

    Kalau kamu hanya login dari IP tetap, batasi SSH lebih ketat lagi:

    sudo ufw allow from 203.0.113.10 to any port 22 proto tcp
sudo ufw delete limit OpenSSH
    Docker melewati UFW

    Port yang di-publish Docker (-p 8080:80) menulis aturan iptables sendiri dan tidak diblokir UFW. Bind ke localhost (-p 127.0.0.1:8080:80) atau gunakan chain DOCKER-USER.

    Opsional: filter koneksi keluar juga (default deny outgoing). Ini efektif menghambat malware yang mencoba "menelepon pulang", tapi kamu harus mengizinkan DNS, NTP, HTTP/HTTPS untuk apt, dan lain-lain secara manual. Cocok untuk server dengan fungsi sempit.

    Rollback

    sudo ufw disable (dari konsol jika SSH sudah terputus).

    05 Minimalkan service & paket P1

    Setiap service yang berjalan adalah permukaan serangan. Kode yang tidak terpasang tidak bisa dieksploitasi.

    # Apa yang mendengarkan di jaringan?
sudo ss -tulpn
# Service yang aktif saat boot
systemctl list-unit-files --type=service --state=enabled
# Timer (cron versi systemd)
systemctl list-timers --all

    Kandidat umum untuk dimatikan di server (cek dulu apakah kamu membutuhkannya):

    ServiceFungsiMatikan jika…
    avahi-daemonmDNS / Bonjourbukan desktop di jaringan rumah
    cups, cups-browsedPrintertidak mencetak (cups-browsed punya CVE serius tahun 2024)
    bluetoothBluetoothserver / tidak dipakai
    ModemManagerModem selulertidak ada modem
    rpcbind, nfs-*NFStidak berbagi file via NFS
    smbd, nmbdSambatidak berbagi file ke Windows
    sudo systemctl disable --now avahi-daemon.service avahi-daemon.socket cups-browsed.service
sudo systemctl mask ctrl-alt-del.target        # cegah reboot tak sengaja via Ctrl+Alt+Del
# Hapus paket klien jaringan lama yang tidak terenkripsi
sudo apt purge -y telnet rsh-client talk ftp 2>/dev/null
sudo apt autoremove --purge -y

    Pastikan service yang hanya dipakai lokal (database, Redis, dll.) mendengarkan di 127.0.0.1, bukan di 0.0.0.0. Cek kolom Local Address di output ss -tulpn.

    06 Fail2ban: blokir brute-force P2

    Fail2ban membaca log dan memblokir IP yang berkali-kali gagal login. Kalau SSH sudah key-only, manfaatnya terutama mengurangi noise. Untuk service yang masih memakai password (web login, mail), manfaatnya jauh lebih besar.

    sudo apt install -y fail2ban
    /etc/fail2ban/jail.local[DEFAULT]
bantime  = 1h
findtime = 10m
maxretry = 5
bantime.increment = true
bantime.maxtime   = 1w
backend  = systemd
banaction = ufw
ignoreip = 127.0.0.1/8 ::1

[sshd]
enabled = true
mode    = aggressive

    Tambahkan IP kamu sendiri ke ignoreip supaya tidak ikut terblokir.

    sudo systemctl enable --now fail2ban
sudo systemctl restart fail2ban
sudo fail2ban-client status
sudo fail2ban-client status sshd
# Membuka blokir IP:
sudo fail2ban-client set sshd unbanip 203.0.113.10

    07 Hardening kernel dengan sysctl P2

    Parameter kernel mengatur perilaku jaringan (redirect, spoofing, SYN flood) dan seberapa banyak informasi internal kernel yang bisa dilihat proses biasa. Informasi itu sering dipakai untuk eksploitasi.

    /etc/sysctl.d/99-hardening.conf# --- Jaringan ---
net.ipv4.conf.all.accept_redirects = 0
net.ipv4.conf.default.accept_redirects = 0
net.ipv6.conf.all.accept_redirects = 0
net.ipv6.conf.default.accept_redirects = 0
net.ipv4.conf.all.secure_redirects = 0
net.ipv4.conf.default.secure_redirects = 0
net.ipv4.conf.all.send_redirects = 0
net.ipv4.conf.default.send_redirects = 0
net.ipv4.conf.all.accept_source_route = 0
net.ipv4.conf.default.accept_source_route = 0
net.ipv6.conf.all.accept_source_route = 0
net.ipv4.conf.all.rp_filter = 1
net.ipv4.conf.default.rp_filter = 1
net.ipv4.conf.all.log_martians = 1
net.ipv4.conf.default.log_martians = 1
net.ipv4.icmp_echo_ignore_broadcasts = 1
net.ipv4.icmp_ignore_bogus_error_responses = 1
net.ipv4.tcp_syncookies = 1
net.ipv4.tcp_rfc1337 = 1
net.ipv6.conf.all.accept_ra = 0
net.ipv6.conf.default.accept_ra = 0

# --- Kernel ---
kernel.kptr_restrict = 2
kernel.dmesg_restrict = 1
kernel.unprivileged_bpf_disabled = 1
net.core.bpf_jit_harden = 2
kernel.yama.ptrace_scope = 1
kernel.randomize_va_space = 2
kernel.sysrq = 0
fs.suid_dumpable = 0
fs.protected_hardlinks = 1
fs.protected_symlinks = 1
fs.protected_fifos = 2
fs.protected_regular = 2
    sudo sysctl --system
sysctl kernel.kptr_restrict net.ipv4.tcp_syncookies   # verifikasi
    Parameter yang bisa merusak sesuatu

    • accept_ra = 0: jangan dipakai jika server mendapat IPv6 lewat SLAAC/router advertisement (umum di VPS). Hapus kedua baris itu kalau IPv6 hilang.

    • rp_filter = 1: bisa memutus routing asimetris (multi-homed, VPN tertentu). Gunakan 2 (loose) kalau bermasalah.

    • Docker, Kubernetes, VPN gateway, dan router membutuhkan net.ipv4.ip_forward = 1. Jangan paksa ke 0 di mesin seperti itu.

    • ptrace_scope = 2 atau lebih memblokir debugger (gdb, strace). Nilai 1 adalah default Ubuntu yang seimbang.

    Matikan core dump

    Core dump bisa berisi password atau kunci dari memori.

    echo '* hard core 0' | sudo tee /etc/security/limits.d/99-nocore.conf
sudo mkdir -p /etc/systemd/coredump.conf.d
printf '[Coredump]\nStorage=none\nProcessSizeMax=0\n' | sudo tee /etc/systemd/coredump.conf.d/disable.conf
    Rollback

    sudo rm /etc/sysctl.d/99-hardening.conf && sudo reboot

    08 Filesystem, mount options & izin file P2

    Banyak exploit mengunduh payload ke direktori yang bisa ditulis siapa saja (/tmp, /dev/shm) lalu menjalankannya. Opsi mount noexec,nosuid,nodev memutus rantai itu.

    Amankan /dev/shm dan /tmp

    /etc/fstab (tambahkan di akhir)tmpfs  /dev/shm  tmpfs  defaults,nodev,nosuid,noexec  0 0
tmpfs  /tmp      tmpfs  defaults,nodev,nosuid,noexec,mode=1777,size=2G  0 0
    sudo systemctl daemon-reload
sudo mount -o remount /dev/shm
sudo mount /tmp          # atau reboot; isi /tmp lama akan tertutup mount baru
findmnt /tmp /dev/shm    # pastikan opsi noexec,nosuid,nodev terlihat
    Efek samping noexec di /tmp

    Beberapa installer pihak ketiga dan script build mengeksekusi file dari /tmp dan akan gagal. Kalau terjadi, jalankan sementara sudo mount -o remount,exec /tmp, lalu kembalikan. Sesuaikan size= dengan RAM kamu, karena /tmp berbasis tmpfs memakai RAM.

    Izin file sensitif

    sudo chown root:root /etc/passwd /etc/group; sudo chmod 644 /etc/passwd /etc/group
sudo chown root:shadow /etc/shadow /etc/gshadow; sudo chmod 640 /etc/shadow /etc/gshadow
sudo chmod 600 /etc/ssh/ssh_host_*_key
sudo chmod 700 /root
sudo chmod 750 /home/*          # default di Ubuntu 21.04+, cek instalasi lama
sudo chmod og-rwx /etc/crontab /etc/cron.d /etc/cron.daily /etc/cron.hourly /etc/cron.weekly /etc/cron.monthly

    Cari file berbahaya

    # Program SUID/SGID: bandingkan dengan daftar yang wajar, curigai yang ada di /home, /tmp, /opt
sudo find / -xdev \( -perm -4000 -o -perm -2000 \) -type f -printf '%M %u %p\n' 2>/dev/null

# File yang bisa ditulis semua orang
sudo find / -xdev -type f -perm -0002 -not -path '/proc/*' 2>/dev/null

# Direktori world-writable tanpa sticky bit
sudo find / -xdev -type d -perm -0002 ! -perm -1000 2>/dev/null

# File tanpa pemilik (sisa user yang dihapus)
sudo find / -xdev \( -nouser -o -nogroup \) 2>/dev/null

    Enkripsi disk

    Untuk laptop dan perangkat yang bisa dicuri, enkripsi disk penuh (LUKS) adalah kontrol terpenting. Pilihannya ada di installer Ubuntu ("Advanced features → Use LVM and encryption"). Mengenkripsi disk sistem setelah instalasi sangat sulit dan praktis butuh instal ulang. Cek apakah sudah aktif:

    lsblk -o NAME,TYPE,FSTYPE,MOUNTPOINT | grep -i crypt

    09 AppArmor (Mandatory Access Control) P2

    AppArmor membatasi apa yang boleh diakses sebuah program, bahkan jika program itu berhasil dibobol. Ubuntu sudah menyalakannya secara default. Tugasmu adalah memastikan profil penting berada di mode enforce.

    sudo aa-status                          # ringkasan profil enforce/complain
sudo apt install -y apparmor-utils apparmor-profiles apparmor-profiles-extra

    Untuk profil baru atau tambahan, gunakan alur complain → uji → enforce:

    sudo aa-complain /etc/apparmor.d/usr.sbin.nginx   # catat pelanggaran saja
# ... jalankan aplikasi seperti biasa beberapa hari ...
sudo journalctl -k | grep -i apparmor | grep -i denied
sudo aa-logprof                                  # perbarui profil secara interaktif
sudo aa-enforce /etc/apparmor.d/usr.sbin.nginx   # aktifkan pemblokiran
    Jangan enforce semua profil sekaligus

    Profil di apparmor-profiles-extra tidak dirancang untuk setiap konfigurasi. Kalau di-enforce massal, service bisa berhenti tanpa pesan error yang jelas.

    10 Logging & audit dengan auditd P2

    Kalau terjadi insiden, pertanyaan pertama adalah "apa yang terjadi dan kapan". Tanpa log yang tersimpan dan audit trail, pertanyaan itu tidak bisa dijawab.

    Journald persisten

    sudo mkdir -p /etc/systemd/journald.conf.d
printf '[Journal]\nStorage=persistent\nSystemMaxUse=1G\nCompress=yes\n' | sudo tee /etc/systemd/journald.conf.d/99-persist.conf
sudo systemctl restart systemd-journald
journalctl --disk-usage

    Pasang auditd

    sudo apt install -y auditd audispd-plugins
sudo systemctl enable --now auditd
    /etc/audit/rules.d/99-hardening.rules# Perubahan identitas & hak akses
-w /etc/passwd -p wa -k identity
-w /etc/group -p wa -k identity
-w /etc/shadow -p wa -k identity
-w /etc/gshadow -p wa -k identity
-w /etc/sudoers -p wa -k sudoers
-w /etc/sudoers.d/ -p wa -k sudoers

# Konfigurasi penting
-w /etc/ssh/sshd_config -p wa -k sshd
-w /etc/ssh/sshd_config.d/ -p wa -k sshd
-w /etc/crontab -p wa -k cron
-w /etc/cron.d/ -p wa -k cron
-w /var/spool/cron/ -p wa -k cron
-w /etc/systemd/system/ -p wa -k systemd

# Login
-w /var/log/lastlog -p wa -k logins
-w /var/run/faillock/ -p wa -k logins

# Perintah yang dijalankan sebagai root oleh user manusia
-a always,exit -F arch=b64 -S execve -F euid=0 -F auid>=1000 -F auid!=unset -k root_cmd

# Load/unload modul kernel
-a always,exit -F arch=b64 -S init_module,finit_module,delete_module -k modules

# Perubahan waktu sistem
-a always,exit -F arch=b64 -S adjtimex,settimeofday,clock_settime -k time_change

# Kunci aturan (butuh reboot untuk mengubah). Aktifkan HANYA setelah aturan stabil.
# -e 2
    sudo augenrules --load
sudo auditctl -l | head                 # aturan aktif
sudo ausearch -k identity --start today # cari berdasarkan key
sudo aureport --summary
sudo aureport --auth --failed
    Kirim log ke luar mesin

    Penyerang yang mendapat root bisa menghapus log lokal. Untuk server penting, teruskan log ke server lain (rsyslog remote, Loki, Wazuh, atau layanan SIEM).

    11 Integritas file & deteksi rootkit P3

    Kalau pencegahan gagal, deteksi adalah lapisan berikutnya. AIDE memberi tahu file sistem mana yang berubah sejak baseline dibuat.

    AIDE

    sudo apt install -y aide
sudo aideinit                                     # membuat baseline (bisa beberapa menit)
sudo cp /var/lib/aide/aide.db.new /var/lib/aide/aide.db
sudo aide --config /etc/aide/aide.conf --check    # bandingkan dengan baseline

    Setelah upgrade paket yang sah, perbarui baseline dengan sudo aide --config /etc/aide/aide.conf --update, lalu salin ulang aide.db.new ke aide.db. Ubuntu sudah menjadwalkan pemeriksaan harian lewat dailyaidecheck.

    Simpan baseline di luar mesin

    Penyerang dengan akses root bisa memperbarui database AIDE. Salin aide.db ke media read-only atau ke mesin lain.

    Verifikasi paket

    sudo apt install -y debsums
sudo debsums -s          # tampilkan hanya file paket yang checksum-nya berubah

    rkhunter

    sudo apt install -y rkhunter
sudo rkhunter --propupd          # simpan properti file saat sistem masih bersih
sudo rkhunter --check --sk --rwo # tampilkan hanya warning

    rkhunter cukup sering memberi false positive (misalnya script di /usr/bin). Teliti setiap warning, dan whitelist lewat /etc/rkhunter.conf.local hanya setelah kamu yakin aman.

    Antivirus (opsional)

    ClamAV berguna untuk server file, mail, atau upload yang melayani klien Windows. Untuk server Linux biasa, manfaatnya kecil dibanding kontrol lain di halaman ini.

    sudo apt install -y clamav clamav-daemon
sudo systemctl stop clamav-freshclam && sudo freshclam && sudo systemctl start clamav-freshclam
clamscan -r -i /home

    12 Nonaktifkan modul kernel yang tidak dipakai P3

    Filesystem dan protokol jaringan yang jarang dipakai adalah kode kernel yang jarang diaudit. Beberapa punya riwayat CVE eskalasi hak akses (misalnya DCCP dan TIPC).

    13 Kunci akun setelah gagal login (faillock) P3

    Ini melindungi login lokal dan konsol dari tebak-tebakan password. Bagian ini paling berisiko di seluruh tutorial: kesalahan PAM bisa membuat tidak ada seorang pun yang bisa login, termasuk lewat sudo.

    Wajib

    Buka sudo -i di satu terminal dan biarkan terbuka sampai pengujian selesai. Backup file terlebih dahulu: sudo cp /etc/pam.d/common-auth /etc/pam.d/common-auth.bak

    /etc/security/faillock.confdeny = 5
unlock_time = 900
fail_interval = 900
audit

    Di /etc/pam.d/common-auth, ubah bagian atas agar urutannya persis seperti ini (baris lain di bawahnya biarkan):

    /etc/pam.d/common-authauth    requisite                       pam_faillock.so preauth
auth    [success=1 default=ignore]      pam_unix.so nullok
auth    [default=die]                   pam_faillock.so authfail
auth    sufficient                      pam_faillock.so authsucc
auth    requisite                       pam_deny.so
auth    required                        pam_permit.so
    /etc/pam.d/common-account (tambahkan di akhir)account required                        pam_faillock.so
    # Uji di terminal LAIN:
sudo -k; sudo true            # harus tetap bisa dengan password benar
sudo faillock --user adminku  # lihat catatan kegagalan
sudo faillock --user adminku --reset
    Catatan pemeliharaan

    Menjalankan pam-auth-update (kadang otomatis saat paket PAM di-upgrade) bisa menimpa common-auth. Setelah upgrade besar, cek ulang isinya. Kalau kamu perlu kepatuhan formal, gunakan Ubuntu Security Guide (bagian 15), yang mengelola ini dengan benar.

    Rollback

    sudo cp /etc/pam.d/common-auth.bak /etc/pam.d/common-auth

    14 Khusus desktop/laptop & keamanan boot P3

    Ancaman utama perangkat pribadi berbeda dari server: pencurian fisik, layar yang tidak dikunci, dan aplikasi yang tidak tepercaya.

    Kunci layar & login

    gsettings set org.gnome.desktop.session idle-delay 300          # layar mati setelah 5 menit
gsettings set org.gnome.desktop.screensaver lock-enabled true
gsettings set org.gnome.desktop.screensaver lock-delay 0
gsettings set org.gnome.desktop.notifications show-in-lock-screen false

    Matikan auto-login: di /etc/gdm3/custom.conf pastikan AutomaticLoginEnable=false.

    Firewall & aplikasi

    • Aktifkan UFW (bagian 04). Di desktop cukup sudo ufw default deny incoming && sudo ufw enable. GUI-nya tersedia di gufw.
    • Pasang aplikasi dari repo resmi, Snap Store, atau Flathub. Hindari .deb acak dan curl … | sudo bash dari sumber yang tidak kamu verifikasi.
    • Cek izin snap: snap connections nama-app. Cabut yang tidak perlu: sudo snap disconnect nama-app:camera.

    Secure Boot

    mokutil --sb-state      # harus "SecureBoot enabled"

    Password GRUB

    Password GRUB mencegah orang dengan akses fisik mengedit parameter boot, misalnya init=/bin/bash untuk mendapat root tanpa password. Tanpa enkripsi disk, manfaatnya terbatas, karena penyerang tetap bisa boot dari USB.

    grub-mkpasswd-pbkdf2       # salin hash "grub.pbkdf2.sha512...."
    /etc/grub.d/40_custom (tambahkan di akhir)set superusers="grubadmin"
password_pbkdf2 grubadmin grub.pbkdf2.sha512.10000.HASH_KAMU

    Secara default, setelah ini setiap boot meminta password. Supaya boot normal tetap otomatis dan hanya edit/recovery yang dilindungi, tambahkan --unrestricted pada entri menu:

    sudo sed -i 's/^CLASS="--class gnu-linux --class gnu --class os"/CLASS="--class gnu-linux --class gnu --class os --unrestricted"/' /etc/grub.d/10_linux
sudo update-grub

    Jangan lupa memasang juga password BIOS/UEFI dan mematikan boot dari USB di firmware.

    15 Ukur hasil: Lynis & Ubuntu Security Guide P2

    Tanpa pengukuran, hardening hanya perasaan aman. Jalankan audit sebelum dan sesudah, lalu bandingkan.

    Lynis

    Versi di repo Ubuntu sering tertinggal. Pakai versi terbaru dari GitHub:

    git clone --depth 1 https://github.com/CISOfy/lynis
cd lynis && sudo ./lynis audit system
# Lihat "Hardening index" dan bagian "Suggestions"
sudo grep -E '^(warning|suggestion)' /var/log/lynis-report.dat | head -40

    Jangan mengejar skor 100. Baca setiap saran dan putuskan apakah relevan untuk ancaman yang kamu hadapi.

    Ubuntu Security Guide (USG): benchmark CIS/DISA-STIG

    Ini alat resmi Canonical untuk audit dan remediasi otomatis berdasarkan CIS Benchmark. Butuh Ubuntu Pro (gratis untuk personal).

    sudo pro enable usg
sudo apt install -y usg
sudo usg audit cis_level1_server       # atau cis_level1_workstation
# Laporan HTML tersimpan di /var/lib/usg/
    usg fix bukan tombol ajaib

    sudo usg fix cis_level1_server mengubah puluhan pengaturan sekaligus, termasuk SSH, PAM, dan firewall. Jalankan hanya di VM uji dulu. Untuk mengecualikan aturan tertentu, gunakan tailoring file (usg generate-tailoring).

    16 Backup & rencana pemulihan P2

    Tidak ada hardening yang 100%. Ransomware dan kesalahan manusia tetap terjadi, dan backup yang teruji adalah satu-satunya jaminan kamu bisa pulih.

    • Aturan 3-2-1: 3 salinan, 2 media berbeda, 1 di luar lokasi (offsite).
    • Immutable / append-only: penyerang yang mendapat root tidak boleh bisa menghapus backup. Gunakan kredensial yang hanya boleh menulis, atau object storage dengan object lock.
    • Uji restore secara berkala. Backup yang belum pernah di-restore belum terbukti bisa dipakai.
    # Contoh dengan restic (terenkripsi, deduplikasi)
sudo apt install -y restic
restic -r sftp:backup@host-lain:/srv/restic init
sudo restic -r sftp:backup@host-lain:/srv/restic backup /etc /home /var/www --exclude-caches
restic -r sftp:backup@host-lain:/srv/restic snapshots
restic -r sftp:backup@host-lain:/srv/restic restore latest --target /tmp/uji-restore
